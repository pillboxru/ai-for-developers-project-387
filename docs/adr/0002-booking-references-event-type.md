# Бронирование ссылается на тип события и не копирует его длительность

Бронирование хранит начало и тип события, а конец вычисляется как начало плюс длительность типа. Решили так, потому что у звонка должен быть один источник длительности, иначе бронирование и тип могут разойтись.

## Considered Options

- Копировать длительность в бронирование. Тогда длительность типа можно менять свободно, но у звонка появляются два источника длительности.

## Consequences

- Длительность типа события нельзя менять, пока у него есть хотя бы одно неотменённое бронирование, включая прошедшие: иначе задним числом изменится время уже прошедших звонков.
- Отменённые бронирования смене длительности не мешают, хотя их конец тоже вычисляется по типу. После смены длительности у предстоящего отменённого бронирования меняется время конца в списке владельца и момент, когда оно уходит из списка. Это допустимо: отменённое бронирование не занимает время.
- Удалить тип с неотменёнными бронированиями тоже нельзя. Чтобы гости его не видели, тип скрывают; для другой длительности владелец создаёт новый тип.
- Тип, у которого остались только отменённые бронирования, удалить можно. Его отменённые бронирования удаляются вместе с ним: без типа их конец не из чего вычислить.
